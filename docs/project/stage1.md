# Stage 1 — Problem Framing

## 阶段结论

CaseTrace 聚焦 **Technical Incident Investigation（技术异常调查）**，以半导体封装质量异常作为主要 Case Study。

## 问题定义

技术异常调查需要综合：

- 当前异常的证据；
- 已结案的历史案例；
- Specification、Quality Agreement、OCAP 等领域知识；
- 调查过程中不断加入的新信息。

这些信息和经验通常分散在不同文件、系统和人员之间，导致调查效率低、历史经验难复用，并且高度依赖资深工程师。

## 系统目标

> 基于当前证据、历史案例和领域知识，为工程师提供有依据的历史参考、分析方向和调查支持。

系统应随着新证据加入持续更新结果，但不替代工程师确认最终 Root Cause。

## 项目定位

| 项目要素 | 定义 |
|---|---|
| 通用问题 | 迭代式技术异常调查 |
| 主要场景 | 半导体封装质量异常 |
| 核心价值 | 降低经验门槛，提高调查效率，复用组织经验 |
| 产品形态 | Case-centered Investigation Workspace / Copilot |
| 目标用户 | 负责技术或质量异常调查的工程师 |

半导体是项目的应用场景，不是理解项目的前提。项目应让非制造业的 CS/AI 导师和面试官也能理解。

## 系统边界

CaseTrace 是调查辅助系统，不是：

- 自动 Root Cause 判定器；
- 万能 AI 助手；
- 只做文档问答的简单 RAG；
- 只生成调查报告的工具；
- MES、QMS 等企业系统的替代品。

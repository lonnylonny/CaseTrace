## Codex Plan

**执行入口：** 先读 [Current Plan](../current-plan.md) 确认活动包，再按 [AGENTS 的 M3 工作流](../../../AGENTS.md#m3-delivery-workflow--user-confirmed-override) 执行。下列要求是本包边界，不是替 Cline 预排的子交付；由 Cline 在 Report 中安排最多 5 个子交付，每次只推进当前一步。

**目标与范围：** 使用 M3-01 的入口在 dev-v2 跑通一种 Embedding 检索，保留逐 Query 对比；这是小数据上的首次接入，不作最终选型结论。

**任务来源与阅读：** [Current Plan](../current-plan.md) 第 4、5 节、[M3-01](m3-01-evaluation-entry.md) 的已验收接口；按需读现有检索、文档构建、runner 和依赖配置。选择模型时核对实际资源与官方模型/库文档，将选定版本及依据写入本包。

**输入 → 输出：** dev-v2 的同一历史文本和 Query → 文档向量、Case ID 映射、Embedding 排名、模型及缓存配置、独立评估结果。

**必须实现的行为：**

- 启动时记录一个模型的版本、运行方式、依赖和资源条件；本地下载或 API 调用的选择在本包内确定，缺资源时如实记录阻塞，不用伪向量冒充模型输出。
- 文档与 Query 按所选模型要求编码；记录前缀、归一化、相似度和截断策略，原始历史文本来源与 BM25 相同。先用小批真实编码，再运行全部三条 Query。
- 小语料直接计算全部文档相似度。缓存绑定模型版本、编码配置、文本哈希和 Case ID；输入或配置变更应失效。模型调用失败、向量数/维度不符、非有限值明确报错；如使用余弦相似度，明确零向量处理。
- 排名同分规则固定，ID 与来源正确对应；记录编码和查询耗时、冷启动/缓存条件，报告实际模型和依赖。真实结果复现记录模型数值误差条件，不要求跨硬件浮点字节完全一致。
- 保持 dev-v2 标签与指标不变，BM25 仍能运行；语义模型对否定与产品 ID 的表现需要观察，不预设其理解正确。

**实现边界：** 新增必要检索实现、最小编码/缓存代码及测试，扩展 CLI 方法和报告配置；用 uv 管理实际需要的依赖。本包不扩充数据、不建向量数据库。

**用户亲手部分（预留）：** 建议用户实现“已计算相似度 → 排名前 K 个 Case”的小段逻辑。输入为对应的 Case ID、相似度及 K，输出遵循 M3-01 的结果契约；明确降序、同分稳定、K 合法及原列表不被修改。Cline 给接口和小样例预期，留函数体给用户；若已有可复用逻辑，则改为用户编写此行为的独立回归测试，避免重复代码。

**测试边界与命令：** 用固定小向量检验可手算排序、Case 映射和异常输入；用替身检验缓存复用及失效，测试不依赖网络下载。通过 `uv run pytest -q tests/evaluation tests/test_cli_evaluate.py tests/test_demo.py` 和本包新增的检索测试；另跑真实模型 smoke check 和同一 dev-v2 的 BM25 / Embedding 评估，完整命令写入 Report。替身测试不算真实模型验证。

**验收与教学停止点：** 模型真实运行、来源/缓存正确、结果可复现并能解释与 BM25 的差异，用户部分已完成检查。讲清编码、相似度、排序、缓存各自职责；停在本包，扩充数据交给 M3-03。

**使用 skills：** Cline 按需读取 [implement](../../../.agents/skills/implement/SKILL.md)、[teach](../../../.agents/skills/teach/SKILL.md)，纯逻辑与回归测试采用 [tdd](../../../.agents/skills/tdd/SKILL.md)；均按 AGENTS 项目适配。Codex 回交时用 [code-review](../../../.agents/skills/code-review/SKILL.md) 分开审阅 Spec / Standards，默认单 agent。
